# Lesson Prototype

완성본을 만들기 전에 판단 가능한 시제품을 만든다.

이 스킬은 polished lesson plan을 만들지 않는다. 작은 prototype을 2~3개 만들고, 교사가 무엇을 배워야 하는지 비교하게 한다.

## Non-negotiables

- 완성 수업안, 완성 활동지, 완성 평가지를 바로 만들지 않는다.
- prototype은 작고 버릴 수 있어야 한다.
- prototype마다 무엇을 검증하려는지 명시한다.
- 학생 개인정보를 요구하지 않는다.
- 참여/표상/표현 장벽을 비교한다.
- 3개를 넘는 후보를 기본으로 만들지 않는다.
- 질문할 때는 가능한 한 3~5개의 선택지와 `기타: 직접 적기`를 제공한다.
- 질문을 더 할지, prototype 비교로 넘어갈지는 `../../../references/interview-readiness.md`의 readiness gate로 판단한다.

## Workflow

### 1. Define the design question

먼저 prototype으로 무엇을 알아볼지 정한다.

```text
이번 prototype으로 무엇을 비교하고 싶나요?

A. 도입 방식
B. 핵심 활동 방식
C. 발문 흐름
D. 평가 장면
E. 피드백 방식
```

### 2. Set comparison criteria

prototype은 같은 기준으로 비교한다.

기본 기준:

- 학습 목표와의 연결
- 학생 사고의 깊이
- 예상 오개념 노출
- 시간 안에 실행 가능성
- 참여/표현 장벽
- 평가 증거의 선명함

### 3. Generate 2~3 prototypes

각 prototype은 짧게 쓴다.

형식:

```text
Prototype A
- 핵심 아이디어:
- 학생이 하는 일:
- 드러나는 학습 증거:
- 장점:
- 위험:
```

### 4. Compare before choosing

바로 하나를 밀어붙이지 않는다.

```text
추천은 B입니다.
이유는 평가 증거가 가장 선명하고, 오개념이 활동 중간에 드러나기 때문입니다.
다만 시간이 부족한 학급에서는 A가 더 안전합니다.
```

### 5. Convert selected prototype

교사가 선택한 prototype만 다음 단계로 확장한다.

확장 가능 산출물:

- 수업 흐름
- 활동지 초안
- 발문 리스트
- 최소 평가 장면
- 루브릭 초안

## Output format

1. 비교하려는 설계 질문
2. 비교 기준
3. Prototype A/B/C
4. 장점·위험 비교
5. 추천안
6. 교사가 선택해야 할 지점
7. 선택 후 확장안

## Review checklist

- prototype이 작고 버릴 수 있는가?
- 각 prototype의 검증 질문이 명확한가?
- 평가 증거가 비교 기준에 포함되었는가?
- 참여/표상/표현 장벽을 비교했는가?
- 완성본 생성으로 너무 빨리 넘어가지 않았는가?
- 개인정보를 요구하지 않았는가?

## Red flags

- 후보를 비교하지 않고 완성안을 바로 만든다.
- 5개 이상의 후보를 만들어 판단을 흐린다.
- prototype마다 비교 기준이 다르다.
- 자료의 예쁨을 prototype 성공 기준으로 삼는다.
- 학생 개인정보를 요구한다.
