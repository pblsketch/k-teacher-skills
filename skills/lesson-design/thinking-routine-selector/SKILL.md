# Thinking Routine Selector

사고 루틴을 예쁜 활동으로 소비하지 않는다. 학생의 사고가 보이고, 말해지고, 수정되도록 수업 흐름에 넣는다.

## Non-negotiables

- 루틴 이름만 추천하고 끝내지 않는다.
- 먼저 수업 목표, 사고 목적, 학생 맥락을 확인한다.
- 질문할 때는 가능한 한 3~5개의 선택지와 `기타: 직접 적기`를 제공한다.
- 질문을 더 할지, 루틴을 제안할지는 `../../../references/interview-readiness.md`의 readiness gate로 판단한다.
- 학생 개인정보, 실명, 민감정보를 요구하지 않는다.
- 학생의 참여/표상/표현 장벽을 낮추는 운영 변형을 포함한다.
- 사고 루틴은 교과 학습과 분리하지 않고 핵심 개념·자료·평가 증거에 연결한다.

## Workflow

### 1. Clarify thinking purpose

먼저 어떤 사고를 보이게 할지 정한다.

- 관찰과 질문
- 근거 기반 추론
- 다관점 탐색
- 개념 형성
- 성찰과 메타인지
- 피드백과 수정

### 2. Select 2-3 candidate routines

`../../../references/thinking-routines-matrix.md`를 참고해 루틴 후보를 고른다.

각 후보에는 다음을 포함한다.

1. 루틴명
2. 적합한 이유
3. 수업 단계
4. 교사 발문
5. 학생 산출물
6. 주의할 장벽

### 3. Adapt to classroom constraints

시간, 학년, 모둠 구성, 자료 형태에 맞게 절차를 조정한다.

```text
추천은 See-Think-Wonder입니다.
이 자료는 학생이 먼저 관찰과 해석을 구분해야 하므로, 설명 전에 사고를 드러내는 루틴이 적합합니다.
```

### 4. Connect to assessment evidence

루틴 결과가 무엇을 보여주는지 명확히 한다.

- 학생 질문의 깊이
- 근거와 해석의 구분
- 개념 변화
- 오개념
- 다음 수업 수정 지점

## Output format

1. 수업 맥락 요약
2. 사고 목적
3. 추천 루틴 2~3개
4. 최종 추천 루틴
5. 단계별 진행 절차
6. 교사 발문
7. 학생 기록 양식
8. 평가 증거와 다음 수업 연결
9. 참여/표상/표현 장벽 조정안

## Review checklist

- 루틴이 수업 목표와 연결되는가?
- 학생 사고가 기록이나 말로 드러나는가?
- 교사가 답을 먼저 말하지 않는가?
- 루틴 결과가 다음 발문이나 평가로 이어지는가?
- 개인정보를 요구하지 않는가?
- readiness gate를 통과했거나 미확정 항목을 표시했는가?

## Red flags

- 사고 루틴 이름만 나열한다.
- 루틴을 수업 내용과 분리된 놀이로 만든다.
- 학생 기록을 평가 증거와 연결하지 않는다.
- 학년과 시간 제약을 무시한다.
