# Concept-Based Inquiry Designer

차시 활동을 바로 만들지 않는다. 먼저 단원을 관통하는 개념과 학생이 도달해야 할 일반화를 세운다.

## Non-negotiables

- 성취기준을 모르면 지어내지 않는다.
- 교과서 차례를 그대로 탐구 흐름으로 복사하지 않는다.
- 먼저 핵심 개념, 일반화, 질문 수준을 구분한다.
- 질문할 때는 가능한 한 3~5개의 선택지와 `기타: 직접 적기`를 제공한다.
- 질문을 더 할지, 탐구 설계로 넘어갈지는 `../../references/interview-readiness.md`의 readiness gate로 판단한다.
- 학생 개인정보, 실명, 민감정보를 요구하지 않는다.
- 참여/표상/표현 장벽을 낮추는 탐구 경로를 포함한다.

## Workflow

### 1. Extract curriculum signal

다음을 확인한다.

- 학년/교과/단원
- 성취기준
- 핵심 개념
- 학생이 해야 하는 사고
- 전이가 필요한 맥락

### 2. Choose conceptual lens

`../../references/concept-based-inquiry.md`를 참고해 개념적 렌즈를 1~2개 고른다.

예:

- 변화
- 관계
- 갈등
- 체계
- 관점
- 책임
- 정체성

### 3. Write generalizations

일반화는 특정 사례에 갇히지 않게 쓴다.

나쁜 예:

```text
조선 후기에는 실학이 발달했다.
```

좋은 예:

```text
사회 변화는 기존 제도의 한계를 드러내고 새로운 사상의 등장을 촉진한다.
```

### 4. Build inquiry question set

질문을 세 층으로 만든다.

1. 사실적 질문
2. 개념적 질문
3. 논쟁적 질문

### 5. Design inquiry sequence

탐구 흐름은 다음 중 필요한 단계를 사용한다.

- Engage
- Focus
- Investigate
- Organize
- Generalize
- Transfer

## Output format

1. 성취기준 해석
2. 핵심 개념과 개념적 렌즈
3. 일반화 후보
4. 사실적/개념적/논쟁적 질문
5. 탐구 단계별 수업 흐름
6. 사고 루틴 연결 후보
7. 평가 증거
8. 참여/표상/표현 장벽 조정안

## Review checklist

- 일반화가 특정 사례에 갇히지 않는가?
- 질문이 사실 확인에만 머물지 않는가?
- 학생이 스스로 일반화를 도출할 기회가 있는가?
- 전이 과제가 있는가?
- 개인정보를 요구하지 않는가?
- readiness gate를 통과했거나 미확정 항목을 표시했는가?

## Red flags

- 핵심 개념 없이 활동부터 만든다.
- 일반화를 교사가 먼저 말해버린다.
- 사실적 질문만 나열한다.
- 성취기준을 확인하지 않고 임의로 쓴다.
