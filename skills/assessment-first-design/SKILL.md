# Assessment-First Design

활동보다 평가 증거가 먼저다.

개발자의 TDD를 수업 설계에 맞게 바꾼다.

- Red: 아직 학생이 배웠는지 확인할 증거가 없다.
- Green: 증거를 드러내는 최소 활동을 만든다.
- Refactor: 활동, 발문, 루브릭, 피드백을 다듬는다.

## Non-negotiables

- 활동지나 수업안을 먼저 만들지 않는다.
- 학생이 보여야 할 증거를 먼저 정의한다.
- 루브릭은 산출물보다 먼저 만든다.
- 평가는 처벌이나 분류가 아니라 학습 확인과 피드백을 위한 장치로 설계한다.
- 학생 개인정보를 요구하지 않는다.
- 질문할 때는 가능한 한 3~5개의 선택지와 `기타: 직접 적기`를 제공한다.

## Workflow

### 1. Define learning evidence

먼저 묻는다.

```text
이 수업 후 학생이 무엇을 하면 배웠다고 볼 수 있나요?

A. 개념을 자기 말로 설명한다
B. 새로운 사례에 개념을 적용한다
C. 근거를 들어 판단한다
D. 절차를 수행한다
E. 산출물을 만든다
F. 기타
```

### 2. Write the evidence statement

학생 행동으로 쓴다.

나쁜 목표:

```text
학생들이 환경 문제의 심각성을 이해한다.
```

좋은 증거:

```text
학생은 두 환경 정책 사례를 비교하고, 더 효과적인 정책을 근거 2개로 설명한다.
```

### 3. Design success criteria

루브릭은 세 가지를 포함한다.

- 무엇을 보면 성공인가?
- 부분 성공은 어떤 모습인가?
- 오개념은 어떤 모습으로 드러나는가?

### 4. Create the smallest assessment

먼저 가장 작은 평가 장면을 만든다.

- 3분 exit ticket
- 한 문장 설명
- 짝 토론 발화
- 비교표
- 짧은 서술형 문항
- 미니 산출물

큰 수행평가는 작은 평가 증거가 명확해진 뒤 만든다.

### 5. Build the lesson backward

평가 증거가 정해진 뒤에 활동을 설계한다.

순서:

1. 증거
2. 루브릭
3. 학생 오개념 확인
4. 활동
5. 자료
6. 피드백

## Output format

1. 학습 증거 문장
2. 성공 기준
3. 간단 루브릭
4. 오개념 신호
5. 최소 평가 장면
6. 수업 활동 흐름
7. 피드백 문장
8. 교사용 검토 체크리스트

## Rubric quality rules

루브릭은 다음을 피한다.

- 성실성, 태도, 노력처럼 목표와 무관한 기준
- "우수/보통/미흡"만 있고 차이가 설명되지 않는 기준
- 학생이 무엇을 해야 하는지 알 수 없는 기준

루브릭은 다음을 포함한다.

- 관찰 가능한 행동
- 산출물의 질
- 근거의 적절성
- 개념 사용의 정확성

## Feedback loop

평가를 만들면 반드시 다음을 묻는다.

```text
이 평가 결과가 낮게 나왔을 때, 다음 차시에서 무엇을 바꿀 것인가?
```

평가는 수업 개선으로 이어져야 한다.

## UDL and accessibility check

평가 증거를 정한 뒤 다음을 확인한다.

- 학생이 이해를 보여줄 수 있는 방식이 하나뿐인가?
- 말하기, 쓰기, 그림, 분류, 선택, 설명 중 대안 표현 방식이 필요한가?
- 과제 형식이 핵심 목표보다 읽기량, 필기량, 기기 사용 능력을 더 크게 요구하지 않는가?
- 참여 장벽을 낮추는 선택지가 있는가?

## Review checklist

- 활동보다 평가 증거가 먼저인가?
- 증거가 관찰 가능한 학생 행동인가?
- 루브릭이 목표와 직접 연결되는가?
- 오개념을 드러내는 장면이 있는가?
- 결과를 다음 수업 수정에 사용할 수 있는가?
- 접근성/표현 방식 대안을 검토했는가?

## Red flags

- "재미있는 활동"을 먼저 만들고 나중에 평가를 끼워 넣는다.
- 루브릭 기준이 태도 중심이다.
- 정답만 확인하고 사고 과정을 보지 않는다.
- 평가 결과를 다음 차시 수정과 연결하지 않는다.
- 학생 개인정보를 요구한다.
