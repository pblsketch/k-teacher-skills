# Improve Lesson Architecture

자료를 더 많이 만들지 않는다. 구조를 깊게 만든다.

흩어진 수업자료를 하나의 수업 모듈로 재구성한다.

## Core idea

얕은 수업 구조:

- PPT 따로
- 활동지 따로
- 퀴즈 따로
- 루브릭 따로
- 피드백 문장 따로
- 성취기준은 마지막에 붙임

깊은 수업 구조:

- 단순한 입구: 수업 목표, 평가 증거, 핵심 질문
- 깊은 내부: 활동, 자료, 발문, 루브릭, 피드백, 보충/심화
- 명확한 연결: 모든 자료가 같은 학습 증거를 향함

## Non-negotiables

- 새 자료를 만들기 전에 기존 자료의 구조를 파악한다.
- 자료 수를 늘리는 것을 개선으로 착각하지 않는다.
- 성취기준, 목표, 평가 증거, 활동의 연결을 먼저 본다.
- 학생 개인정보를 요구하지 않는다.
- 교사가 최종 판단해야 할 구조적 선택을 표시한다.

## Workflow

### 1. Inventory existing materials

먼저 기존 자료를 분류한다.

- 설명 자료
- 활동 자료
- 평가 자료
- 피드백 자료
- 보충 자료
- 심화 자료
- 행정/안내 자료

자료가 없으면 다음을 요청한다.

```text
기존 자료 중 하나만 먼저 주세요. PPT 목차, 활동지 문항, 평가 기준 중 무엇이든 괜찮습니다.
```

### 2. Identify the public interface

수업 모듈의 입구를 세 가지로 정한다.

1. 핵심 질문
2. 학습 증거
3. 성공 기준

이 세 가지가 불명확하면 자료를 재구조화하지 않는다.

### 3. Map material dependencies

각 자료가 무엇에 기여하는지 표시한다.

- 목표 이해
- 개념 형성
- 오개념 드러내기
- 연습
- 평가 증거 수집
- 피드백
- 전이/적용

어느 항목에도 기여하지 않는 자료는 제거 후보로 둔다.

### 3.5 Run the deletion test

자료를 제거했을 때 무엇이 일어나는지 묻는다.

```text
이 자료를 지우면 복잡성이 사라지는가,
아니면 필요한 사고가 다른 자료로 흩어지는가?
```

판정:

- **Delete**: 목표/증거와 연결되지 않고 제거해도 학습 흐름이 유지된다.
- **Merge**: 역할은 있지만 다른 자료와 합치면 더 단순해진다.
- **Deepen**: 자료 자체는 필요하지만 핵심 질문, 평가 증거, 피드백과 연결해야 한다.
- **Keep**: 수업 모듈의 public interface와 직접 연결된다.

### 4. Deepen the module

흩어진 자료를 다음 구조로 묶는다.

```text
Lesson Module
├─ Public Interface
│  ├─ 핵심 질문
│  ├─ 학습 증거
│  └─ 성공 기준
├─ Learning Path
│  ├─ 도입 발문
│  ├─ 개념 형성 활동
│  ├─ 적용 활동
│  └─ 정리/전이
├─ Assessment
│  ├─ 최소 평가 장면
│  ├─ 루브릭
│  └─ 피드백 문장
└─ Support
   ├─ 보충
   └─ 심화
```

### 5. Propose refactor steps

수정은 작은 단계로 제안한다.

좋은 제안:

- 활동지 1번 문항을 핵심 질문과 연결한다.
- PPT 설명 슬라이드 3장을 학생 탐구 질문 2개로 바꾼다.
- 퀴즈 문항 2개를 exit ticket으로 재배치한다.
- 루브릭 기준을 활동지 산출물과 연결한다.

나쁜 제안:

- 전체 수업을 완전히 새로 만든다.
- 자료를 더 풍성하게 한다.
- 다양한 활동을 추가한다.

### 6. Candidate report before rewriting

바로 전체 재작성하지 않는다. 먼저 개선 후보를 보고한다.

```text
Strong candidate:
- 이유:
- 바꿀 자료:
- 기대 효과:

Worth exploring:
- 이유:
- 확인 질문:

Speculative:
- 이유:
- 보류 조건:
```

교사가 후보를 고르면 그 후보만 세부 설계한다.

## Output format

1. 현재 자료 구조 요약
2. 핵심 연결 끊김 지점
3. 수업 모듈의 public interface
4. 자료별 역할 재배치
5. 삭제 테스트 결과
6. Strong / Worth exploring / Speculative 후보 리포트
7. 제거/통합/수정 후보
8. 깊은 수업 모듈 초안
9. 단계별 개선 작업
10. 검토 체크리스트

## Review checklist

- 핵심 질문이 있는가?
- 학습 증거가 명확한가?
- 모든 자료가 목표/증거 중 하나와 연결되는가?
- 제거해도 되는 자료가 표시되었는가?
- 보충/심화가 구조 안에 들어와 있는가?
- 새 자료 생성보다 재구조화가 먼저인가?
- 참여/표상/표현 장벽을 줄이는 구조 개선이 있는가?
- 삭제 테스트와 후보 리포트를 거쳤는가?

## Red flags

- 기존 자료를 보지 않고 새 자료를 만든다.
- 자료가 많아지는 것을 개선으로 본다.
- 활동의 재미를 구조의 깊이로 착각한다.
- 평가와 피드백이 수업 끝에 따로 붙어 있다.
- 교과서 순서를 수업 구조로 착각한다.
