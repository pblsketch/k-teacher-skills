# Diagnose Lesson Failure

수업 실패를 감으로 해석하지 않는다.

관찰 가능한 증거를 바탕으로 원인을 좁히고, 다음 차시에서 검증 가능한 작은 수정을 만든다.

## Non-negotiables

- 학생 탓으로 바로 결론 내리지 않는다.
- 교사 탓으로도 바로 결론 내리지 않는다.
- 먼저 관찰 가능한 증거를 묻는다.
- 실제 학생 이름이나 민감정보를 요구하지 않는다.
- 한 번에 전체 수업을 갈아엎지 않는다.
- 다음 차시에서 확인 가능한 최소 수정안을 만든다.
- 질문할 때는 가능한 한 3~5개의 선택지와 `기타: 직접 적기`를 제공한다.
- 질문을 더 할지, 진단 가설로 넘어갈지는 `../../references/interview-readiness.md`의 readiness gate로 판단한다.

## Diagnosis loop

개발자의 디버깅 루프를 수업에 맞게 바꾼다.

1. Reproduce: 무엇이 실제로 일어났는가?
2. Minimize: 실패가 가장 선명하게 드러난 장면은 어디인가?
3. Hypothesize: 가능한 원인은 무엇인가?
4. Instrument: 다음에 무엇을 관찰하면 원인을 구분할 수 있는가?
5. Fix: 가장 작은 수정을 한다.
6. Regression-test: 다음 차시에서 나아졌는지 확인한다.

## Falsifiable hypothesis format

가설은 반드시 반증 가능하게 쓴다.

형식:

```text
만약 [원인]이 문제라면,
[작은 수정]을 했을 때,
다음 차시에서 [관찰 가능한 변화]가 나타날 것이다.
```

예:

```text
만약 선행 개념어가 문제라면,
도입에서 핵심 용어 3개를 학생 언어로 다시 정리했을 때,
exit ticket에서 개념어 오용이 줄어들 것이다.
```

나쁜 가설:

```text
학생들이 집중을 안 한 것 같다.
```

## First question

항상 증거부터 묻는다.

```text
수업이 안 됐다고 느낀 가장 구체적인 증거는 무엇인가요?

A. 학생 발화가 거의 없었다
B. 활동 산출물이 목표와 달랐다
C. 평가/퀴즈 결과가 낮았다
D. 특정 설명 이후 질문이 많아졌다
E. 시간 안에 활동이 끝나지 않았다
F. 기타
```

## Failure categories

가설은 다음 범주로 나눈다.

### Goal mismatch

수업 목표와 활동이 맞지 않는다.

신호:

- 학생은 열심히 했지만 목표와 다른 산출물을 냈다.
- 활동은 재미있었지만 핵심 개념이 드러나지 않았다.

### Prior knowledge gap

선행 지식이 부족하다.

신호:

- 설명 초반부터 막힌다.
- 기초 용어 질문이 반복된다.

### Cognitive load

한 번에 처리할 정보가 너무 많다.

신호:

- 절차는 이해했지만 동시에 적용하지 못한다.
- 활동지 지시문을 계속 다시 읽는다.

### Misconception

오개념이 드러났다.

신호:

- 비슷한 틀린 답이 반복된다.
- 학생들이 자신 있게 틀린 설명을 한다.

### Activity design

활동 구조가 목표를 유도하지 못한다.

신호:

- 모둠 활동이 역할 분담 없이 흘러간다.
- 산출물 형식이 사고를 가린다.

### Assessment mismatch

평가가 수업에서 다룬 사고와 다르다.

신호:

- 수업 중에는 잘한 학생이 평가에서 무너진다.
- 평가 문항이 목표보다 어렵거나 다른 능력을 요구한다.

## Output format

1. 관찰된 증거
2. 가능한 원인 가설 2~4개
3. 각 가설의 반증 가능한 예측
4. 가장 가능성 높은 원인
5. 원인을 구분할 추가 관찰 질문
6. 다음 차시 최소 수정안
7. 수정 효과 확인 방법
8. 재발 방지 체크리스트

## Minimal fix rule

다음 차시 수정은 작아야 한다.

좋은 수정:

- 도입 질문 하나 바꾸기
- 예시를 한 개 추가하기
- 활동 지시문을 두 단계로 나누기
- 루브릭 기준 하나를 학생 언어로 바꾸기
- exit ticket 한 문항 추가하기

나쁜 수정:

- 단원 전체 재설계
- 자료 전부 다시 만들기
- 모든 학생을 수준별로 재분류하기

## Review checklist

- 실패 판단의 증거가 있는가?
- 원인 가설이 여러 개 제시되었는가?
- 각 가설이 "만약-수정-관찰" 형식으로 검증 가능한가?
- 학생 탓/교사 탓으로 단정하지 않았는가?
- 다음 차시 수정이 작고 검증 가능한가?
- 개인정보 없이 진단 가능한가?
- 학생의 참여/표현/이해 장벽 가능성을 검토했는가?

## Red flags

- "학생들이 집중을 안 했다"로 끝낸다.
- 수업 전체를 바로 갈아엎는다.
- 평가 결과만 보고 수업 목표를 바꾸지 않는다.
- 관찰 증거 없이 원인을 확정한다.
- 실제 학생 사례나 이름을 요구한다.
