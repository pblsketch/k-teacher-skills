# Rubric Quality Guard

루브릭을 바로 만들지 않는다. 먼저 무엇이 학습의 증거인지, 준거가 과제 구성요소와 섞이지 않았는지 검토한다.

## Non-negotiables

- 표지, 분량, 그림 수처럼 과제 구성요소를 평가 준거로 삼지 않는다.
- "우수함/보통/미흡" 같은 평가적 판단만 쓰지 않는다.
- 수준 기술은 관찰 가능한 학생 수행으로 쓴다.
- 먼저 성취기준, 과제, 평가 증거를 확인한다.
- 질문할 때는 가능한 한 3~5개의 선택지와 `기타: 직접 적기`를 제공한다.
- 질문을 더 할지, 루브릭 개선으로 넘어갈지는 `../../references/interview-readiness.md`의 readiness gate로 판단한다.
- 학생 개인정보, 실명, 민감정보를 요구하지 않는다.
- 참여/표상/표현 장벽을 낮추는 자기평가·동료평가 대안을 고려한다.

## Workflow

### 1. Identify evidence

학생 작품의 어떤 특성이 학습 증거인지 확인한다.

### 2. Check criteria quality

`../../references/rubric-quality.md`를 기준으로 준거를 점검한다.

- 성취기준과 직접 연결되는가?
- 서로 독립적인가?
- 관찰 가능한가?
- 과제 요구사항이 아니라 학습의 질을 보는가?

### 3. Rewrite level descriptors

수준 기술은 평행 구조로 쓴다.

나쁜 예:

```text
매우 잘함 / 잘함 / 보통 / 미흡
```

좋은 예:

```text
근거를 2개 이상 들어 주장과 연결하여 설명한다.
근거를 제시하지만 주장과의 연결 설명이 일부 부족하다.
```

### 4. Add use guidance

루브릭을 수업 전, 과정 중, 평가 후에 어떻게 쓸지 제안한다.

## Output format

1. 현재 루브릭 문제 진단
2. 성취기준과 평가 증거
3. 개선된 평가 준거
4. 수준별 수행 기술
5. 배점 또는 가중치
6. 학생용 자기점검 문장
7. 교사용 채점 유의점
8. 참여/표상/표현 장벽 조정안

## Review checklist

- 준거가 과제 구성요소가 아니라 학습 증거인가?
- 수준 기술이 관찰 가능한가?
- 수준 간 차이가 같은 측면의 질적 차이인가?
- 성취기준에 없는 일반 역량을 독립 준거로 과도하게 쓰지 않았는가?
- 개인정보를 요구하지 않는가?
- readiness gate를 통과했거나 미확정 항목을 표시했는가?

## Red flags

- 분량, 제출 형식, 그림 개수를 핵심 준거로 삼는다.
- 모든 수준이 모호한 칭찬말로만 되어 있다.
- 성취기준과 연결되지 않는다.
- 학생이 루브릭을 보고 무엇을 고쳐야 할지 알 수 없다.
